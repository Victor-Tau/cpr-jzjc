# v2.0.0：检测内核切换为 lm-detector（Rust 原生）

宿主范围：`>=3.53.1,<3.54.0`。平台：Linux x86_64 / ARM64（aarch64），glibc 2.36+。

## 主要变化

- **检测内核改为 [lm-detector](https://github.com/Ikaleio/lm-detector)**。ModelTrace 已停止更新样本库；评分代码直接采用 lm-detector 官方 Rust SDK（lmfpd 0.2.0），检测逻辑与上游一致，未做修改。内置参考库覆盖 75 个模型（检测器 SHA-256 `a55d4bb2…`）。
- **移除 Python/NumPy 运行时**。评分在插件进程内完成：首次解码参考库约 30 ms，每轮评分为毫秒级；不再解压约 91 MB 运行时、不再启动子进程，安装包也不再包含 `runtime/runtime.tar.gz`。
- **新增「每轮挑战数」（1–3，默认 1）**。lm-detector 只为每轮 3 个有效回答给出校准置信度：
  - 设为 3：有置信度，概率阈值和低置信度复测照常生效；每轮请求量与 Key 用量约为 3 倍。
  - 设为 1–2：只有排名，概率阈值不生效；最高候选在降级名单内并达到连续确认轮数即判定降智。此时建议把「连续确认轮数」设为 2 或以上。
  - 回答不像语言模型输出时不给排名，按低置信度在复测预算内重试。失败重试按单个挑战计。
- **指纹库在线更新改用 lm-detector 官方数据**：`https://lm.ikale.io/data/`，失败时使用 `cdn.jsdmirror.com/npm/lmfpd-data@latest/`；下载后校验检测器 SHA-256 并做离线评分自检。存储空间最多保留两份（当前版本与回退版本）。
- 报告与账户列表在没有置信度时显示「仅排名」和排名分；降级模型名单上限提高到 128 个。

## 升级说明

通过宿主更新现有插件实例。升级后：

- ModelTrace 旧指纹库被删除，自动切换到内置 lm-detector 库；配置中新库不存在的降级模型和别名会被移除（默认的 `gpt-5.6-luna` 在新库中，会保留）。
- 进行中的检测会结束并提示重新检测；配置、计划和历史报告保留。
- 默认请求模型 `gpt-6.1-sol` 不在 lm-detector 参考库内，结果是库内封闭集合排序。开启自动关闭调度前，建议先用几个正常账户实测。
