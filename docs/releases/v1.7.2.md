# v1.7.2

修复 1.7.1 探针结果在校验、保存和重启恢复时丢失的问题，减少批量检测误报「上一次探针执行被中断」。

- 「有效数字不足」等样本校验失败继续复用健康的 Python/NumPy 评分进程，避免逐个重启耗尽维护收尾预算。
- 同批回答先逐个保存原始结果，再校验和评分。维护取消、进程重启或保存确认超时后，重新读取持久化状态，继续处理已保存的回答和样本，不重复发送模型请求。原始回答只存入宿主私有状态，校验完成后删除，不暴露给管理报告。
- 重启后保留排队任务；只有已发出、且没有已保存结果的请求才标记为中断。
- 每批请求都检查扣除收尾预算后的完整窗口，预算不足时顺延且不消耗采样尝试。连续两次完整窗口超时按该批目标窗口判断，覆盖 16 路并发。
- 完成事件后继续读取宿主流结束通知，避免正常完成被提前关闭记为取消；EOF 收尾超时仍保留已确定结果。
- 明确返回 `token_revoked` 或 `kind=unauthorized` 的认证错误，提示在宿主刷新凭据或重新授权，并立即停止检测，不评分、不自动停用账户。
- 数字数量门槛、解析、指纹和评分算法保持原样。宿主 30 秒维护预算内确实没有产生足够数字的回答仍会失败；升级无法恢复失效的上游凭据。
- 更新现有 1.7.1 实例保留配置、计划、历史、指纹库与提交去重。之前已结束的失败或中断任务需重新发起检测。

适配 **Codex Proxy RS >=3.30.2、<3.31.0**，Linux x86_64、glibc 2.36+。包含私有 Python/NumPy 评分运行时，无需额外安装 Python。

下载 `personal.modeltrace-health-1.7.2-x86_64-unknown-linux-gnu.tar.gz` 及对应 `.sha256`，在宿主插件管理中更新并切换现有实例。

安装包大小 30,755,618 字节，SHA-256：`42ab5faee9901af540ab155220c48c307717847531f1485e3208426dbdb71086`。

全部编译使用单个 CPU 核心。构建、回归和升级验证见[验证记录](https://github.com/Victor-Tau/jzjc/blob/v1.7.2/docs/verification.md)。
