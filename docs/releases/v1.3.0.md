# 账号降智检测 1.3.0

本版优化检测耗时、请求中断和页面进度刷新。

- 一次维护回调连续完成准备、请求、样本校验和评分，预算充足时一轮只需一次回调，减少原先步骤间约90秒的调度等待。
- 复用 Python/NumPy 评分进程与指纹库缓存；首次解包在工作线程执行，后续任务复用运行时。
- 按宿主本次调用的剩余预算设置请求期限，预留校验与保存时间。慢请求正常记录超时并重试，降低「上一次探针执行被中断」的发生率；真正的重启及请求结果不确定时仍保留中断保护。
- 独立进度和报告快照，模型请求期间也能读取进度和取消。显示阶段耗时、已接收字节数和复测倒计时。
- 活跃任务每秒刷新、空闲每10秒刷新；隐藏页面暂停，返回立即刷新。报告随检测自动更新，未变化的列表不重复传输。
- 等待复测的账户不再阻塞其他已就绪账户。

适用于 **Codex Proxy RS >=3.29.1、<3.30.0；Linux x86_64、glibc 2.36+**。上传附件中的 `personal.modeltrace-health-1.3.0-x86_64-unknown-linux-gnu.tar.gz` 安装，`.sha256` 附件用于校验。包内包含私有 Python/NumPy，无需另外部署 ModelTrace。

RS 3.29.1 仍有30秒维护调用预算，首次调度及重试、复测仍受30秒维护间隔影响。超过可用预算的模型请求需要宿主支持更长调用，修改插件超时配置不能突破该限制。升级保留配置和历史；先前已中断的任务需重新提交。

验证：10 项 Rust、6 项 Python、21 项实际发布二进制 RPC 集成测试，以及桌面/手机浏览器交互与实时刷新测试。集成使用模拟宿主与模型事件，未发送真实账户检测请求。详细记录与复现方法见仓库 `docs/verification.md`。
