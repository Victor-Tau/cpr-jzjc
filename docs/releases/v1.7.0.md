# v1.7.0

参数配置新增「并行检测数」，批量检测在单次维护回调内并行推进多个账户。

- 后台维护回调内的模型检测请求改为按批并行：默认同时检测4个账户，可在参数配置「并行检测数」调整（1至16；设为1即原有串行行为）。批量检测的等待时间约从「账户数 × 单次请求耗时」降为「批数 × 单次请求耗时」。
- 并行探测各自按提交账户绑定路由与代理，互不影响；同回调配发仍按手动/自动来源交替与运行中优先排序，每个任务每次回调仍最多推进一轮或一次失败尝试，调度公平性与重试预算不变。
- 冷启动保护按批生效：本次回调第一批探测保持完整的准备与请求窗口检查，准备不足时先保存挑战、顺延到下一次回调发起；第二批起可在剩余窗口内继续。有效样本仍在回调内立即评分，评分与状态按完成顺序串行执行，评分进程继续串行复用。
- 并行探测统一按各自的请求窗口记账；宿主预算耗尽时与串行一致记为预算超时，连续两次完整窗口超时提前终止。取消会对并行探测逐一生效并关闭对应模型流。
- 新配置项随插件私有状态保存，宿主配置结构不变；升级保留原有配置、自动计划、指纹库和检测历史，旧配置缺省时按默认4生效。

适配 **Codex Proxy RS >=3.29.7、<3.30.0**，Linux x86_64、glibc 2.36+。
