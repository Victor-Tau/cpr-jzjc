# v1.14.0 — 修复请求日志触发并优化界面

- 宿主版本：`>=3.38.1,<3.39.0`，与 1.13.0 相同。
- SDK 与官方打包工具仍固定至 CPR v3.38.1（`e0b7a841ca074f17e11dad73f39a159c75cb2fb1`）。
- 继续使用 RPC v7、管理能力 v2、180 秒维护预算、UI 0.8.0、原有私有状态 schema 与 Python/NumPy 运行时。

## 修复：请求日志错误码未触发检测

用户反馈：触发错误码设为 `503`，CPR 已记录 `OpenAI upstream failure: kind=upstream_capacity_unavailable, status=503`，对应账户却没有被检测。

原因（CPR 3.38.1）：

- 1.11.0–1.13.0 读取 `/api/admin/usage/records?status=all&period=today` 的首页 100 条，匹配 `errorCode` 或 `statusCode`。CPR 3.38.1 的该列表不含 HTTP 状态字段，`errorCode` 为提供方错误码（如 `server_is_overloaded`），不会是 `503`；`503` 只出现在诊断信息的 `status=503` 中。
- CPR 切换到其他账户后恢复的失败只记录为运维错误事件，不写入用量记录。
- 只读取当天最新 100 条记录，错误较多时会漏掉更早的失败。

新行为：

- 改为读取 CPR 运维错误日志（`/api/admin/operations/errors`），从上次读取时间开始按时间窗口获取，并回读最近 5 分钟以覆盖延迟写入的记录。开启后首次读取回看 15 分钟，停机后最多补读 60 分钟；每次维护最多读取 10 页、每页 50 条，维护约每 30 秒运行一次。
- 匹配上游状态、客户端状态和诊断信息中的 `status=NNN`，包括 CPR 已切换到其他账户重试的中间失败。
- 按账户 ID 匹配账户，其次按邮箱或名称；仍只为启用的 OpenAI 账户排队。
- 排除插件自身的检测请求（插件请求类型与本实例 ID，或任务记录的请求 ID），避免检测失败再次触发检测。
- 新增「触发冷却」（`triggerCooldownMinutes`，默认 30 分钟，可设 0–1440）：同一账户在冷却期内最多由日志触发一次检测，已有活动检测的账户直接跳过。已处理的日志条目持久化去重，保留最近 1024 条。
- 读取失败不阻塞检测和其他维护任务，错误显示在页面上。
- 日志触发的任务可通过账户页「停止日志触发队列」单独停止；管理接口 `api/cancel` 的 `source` 新增 `error_code`。
- 账户页和参数配置显示触发状态：监听的错误码、最近读取、最近命中（账户、错误码、时间）、累计触发次数与读取错误。日志触发的任务标注来源（如「日志触发 503」），报告增加触发来源，包含状态码、请求 ID、诊断信息和观察时间。
- 配置备份与导入包含触发冷却；旧版本导出的配置导入后按 30 分钟补齐。

## 界面优化

- 账户页：顶部增加全部账户、检测队列、确认降智、自动检测和日志触发统计卡片；工具栏更紧凑；结果以彩色标签显示，检测时间附手动、定时或日志触发来源；状态、订阅与分组标签样式统一。
- 检测报告：增加结果摘要和触发来源；概率条中突出降级名单模型；账户操作失败与重试提示更清晰；配置快照和请求记录可折叠。
- 参数配置：按检测请求、降智判定与复测、确认降智后的处理、请求日志触发、自动定时检测、ModelTrace 指纹库、配置备份分组；触发错误码与冷却时间移至独立的「请求日志触发」分区；说明文字更简短，保存栏固定显示并提示未保存修改。
- 检测历史与其他页面使用一致样式，支持明暗主题与移动端布局。

## 安装与升级

下载 `personal.modeltrace-health-1.14.0-x86_64-unknown-linux-gnu.tar.gz`，在 CPR 插件管理中上传并切换现有实例。现有配置、计划、历史和指纹库保留，已有配置的触发冷却默认为 30 分钟。包包含私有 Python/NumPy 运行时，要求 Linux x86_64、glibc 2.36+。

已配置触发错误码的实例，升级后首次维护会回看最近 15 分钟的运维错误日志，匹配到的账户可能随即排队检测。

安装包与 `.sha256` 校验文件随 Release 发布。单核构建与回归结果见 [验证记录](../verification.md)。
