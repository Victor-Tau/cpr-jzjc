# 账号降智检测 1.4.1

修复1.3引入的请求提前超时：准备与请求合并后，准备阶段耗时及额外6秒预留缩短了请求窗口。用已发布的1.2和1.4二进制对照，相同25秒返回的模拟请求在1.2成功，1.4约22.5秒主动超时；本版恢复通过。

- 30秒维护回调中的请求窗口恢复到约28秒。冷启动准备较慢时，保存挑战并在下一次回调发起请求，不消耗尝试次数。已接收的有效样本保留，评分可延后执行。
- 等待重试时显示失败原因和本轮尝试次数。打开的报告自动刷新失败请求，无需手动点击；请求记录增加耗时、已接收流数据量和实际请求窗口。
- 连续两次超过维护调用预算时停止任务，避免继续重复超时；用户配置超时及普通采样失败仍保留最多5次尝试。超时、失败和不完整回答均不触发关闭调度或移组。
- 保留1.4默认参数、降智后两项独立操作、配置备份及1.3时区逻辑。同实例升级保留已有配置、指纹库和历史；更新后对之前失败或中断的任务重新发起检测。

上传附件 `personal.modeltrace-health-1.4.1-x86_64-unknown-linux-gnu.tar.gz` 更新现有实例，`.sha256` 用于校验。适用于 **Codex Proxy RS >=3.29.1、<3.30.0；Linux x86_64、glibc 2.36+**，内含 Python/NumPy，无需另外部署 ModelTrace。插件仍遵守宿主单次维护调用预算；本次修复不要求更新宿主。
