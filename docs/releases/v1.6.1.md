# v1.6.1

修复账号测试正常、插件检测却在约一秒内失败的问题。

- 支持 RPC v5 的原生 WebSocket 模型事件。此前首个 `codex.response.metadata` 事件会被插件误判为不支持的载荷，提前关闭流，宿主显示 `Cancelled / receiver_dropped`，报告显示正文和流数据均为0。
- 优先使用宿主提供的 JSON 解析视图；没有解析视图时解析完整 WebSocket 消息。元数据事件继续等待正文，完成事件及时结束接收。
- 按原始 WebSocket 消息字节数统计流数据。正文、推理、完成快照、输出上限部分结果与明确失败沿用原有规则。
- 保留 JSON/SSE 路径、指定账号与代理路由，以及现有实例的配置、定时计划、指纹库、检测历史和提交去重。

适配 **Codex Proxy RS >=3.29.7、<3.30.0**，Linux x86_64、glibc 2.36+。

下载附件 `personal.modeltrace-health-1.6.1-x86_64-unknown-linux-gnu.tar.gz`，在宿主插件管理中更新并切换现有实例，然后重新提交此前失败的检测。包含私有 Python/NumPy 评分运行时。

全部编译通过 CPU 亲和性限制在一个核心，Cargo 并发任务数为1。本次按要求跳过 SHA-256 校验；打包工具仅生成宿主安装格式必需的摘要字段与附件。

16项 Rust 单元测试、6项评分测试、47项安装包 RPC 回归以及 1.6.0 → 1.6.1 升级验证通过。

验证结果见[验证记录](https://github.com/Victor-Tau/cpr-jzjc/blob/v1.6.1/docs/verification.md)。
