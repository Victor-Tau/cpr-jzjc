# v1.7.1

适配 Codex Proxy RS 3.30.2，修复维护回调被取消后检测任务长期停在「正在接收回答」的问题，并将检测历史改为保留最近三天。

- 检测历史固定保留最近 3 天，不再限制 500 条；提交检测和每次后台维护时清理过期记录。旧配置中的 `retentionDays` 在载入时归一化为 3，参数页不再提供手动保留天数。记录仍受约 12 MiB 历史存储预算保护。
- 修复维护 RPC 被宿主取消后，`pendingProbe` 任务被后续调度永久跳过的问题。维护或管理调用被取消时，下一次调用会强制重新读取持久化状态；结果不确定的探针标记为中断并提示重新检测，不会永久卡住，也不会静默重发模型请求。
- 并行批次按并发数预留收尾时间，先把同批所有探针结果校验并保存，再使用剩余预算评分。评分或保存遇到截止时间时保留已落盘样本，下一次回调优先继续评分，不重发请求。单任务请求窗口约 29 秒，16 路并发约 26.5 秒。
- 账户已位于目标分组时直接完成移组，不再重复写入；移组或关闭调度在维护截止时保留待办并在下一回调幂等重试，避免把预算耗尽误报为操作失败。
- 前端使用进度更新时间判断接收状态：`receiving` 超过 8 秒无更新时显示「进度已过期，等待后台恢复」，其他阶段长时间无更新也会提示，不再持续累计旧进度秒数。
- 使用 Codex Proxy RS 3.30.2 对应提交的 SDK 和 `cpr-plugin` 重新编译，宿主兼容范围为 `>=3.30.2,<3.31.0`；继续使用 RPC v5、管理能力 v2 和协议 v5 安装包。
- UI 组件包更新至 `@codex-proxy/ui` 0.6.0，并启用简体中文语言包。
- 更新现有实例保留配置、自动计划、指纹库、检测历史与提交去重；1.7.0 实例可直接升级。

适配 **Codex Proxy RS >=3.30.2、<3.31.0**，Linux x86_64、glibc 2.36+。
