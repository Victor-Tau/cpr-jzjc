# Linux ARM64 支持与双架构构建验证

> 本记录对应 PR #5 合并前的贡献者本地验证（基于 1.19.0）。1.21.0 的发布验证见 [验证记录](verification.md)。

验证日期：2026-11-09。基于上游提交 `7b1490ec58e80849680086d520feaa921332d4c5`，保留插件版本 1.19.0、CPR 范围 `>=3.43.0,<3.44.0` 和 SDK 固定提交。本改动增加 ARM64 构建与验证，不修改业务逻辑、评分算法、私有状态 schema 或宿主兼容范围。

## 构建与自动化

- 共用 `scripts/package.sh`，通过 `CPR_TARGET` 选择 x86_64 或 aarch64。
- `scripts/runtime_target.py` 集中固定两种基础镜像、wheel 摘要入口、加载器、库目录及 ELF 机器类型。
- `scripts/install_packager.py` 从 SDK 声明的提交安装官方 CLI；验证脚本从源码 manifest 核对版本与宿主范围。
- GitHub Actions 为每个目标使用独立原生 runner 和 Python 3.11.17 / Debian 12 容器。PR 和主分支构建两种目标，标签发布等待两个任务成功后上传两套包和摘要。
- 复用旧运行时会先核对包目标、资源摘要及实际 ELF 架构，失败时保留现有运行时。

## 本地验证环境

在 macOS ARM64 的 Linux 容器环境验证。ARM64 原生构建；x86_64 使用 Debian 12 交叉编译器构建，并在 `linux/amd64` 容器的仿真环境实际运行。使用 Rust 1.99.1、Python 3.11.17、NumPy 2.4.3、Node.js 24、pnpm 9.12.2。

两个发布二进制所需最高 GLIBC 符号均为 2.34，整体按 glibc 2.36+ 环境交付。

此外，旧的本地 CPR 3.44 安装包会被当前源码的版本校验正确拒绝，避免把不同版本的构建产物视为本次发布包。

## 发布流程校验

`actionlint 1.7.12`、Python 语法、shell 语法及 `git diff --check` 通过。工作流固定的官方 Action 提交及输入已核对，`crane v0.22.1` 的安装、基础镜像拉取、归档格式与固定配置摘要通过本地验证。

执行工作流中的发布完整性检查和模拟 CLI 调用，确认：两种架构的四个文件齐全才可发布；缺少摘要会拒绝；先创建草稿，再上传文件；上传失败后不会执行发布草稿的命令。模拟没有调用远程发布接口。
