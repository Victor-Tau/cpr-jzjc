# 账号降智检测 · Codex Proxy RS 插件

使用 [ModelTrace](https://github.com/xqy2006/ModelTrace) 的数字指纹挑战检测账户实际输出更接近哪个候选模型，支持自动复测、定时检测、确认后关闭账户调度、移入指定分组，以及在线更新指纹库。

## 安装

适配 **Codex Proxy RS >=3.29.7、<3.30.0**，发布包适用于 Linux x86_64、glibc 2.36+。运行模式为 `trustedProcess`。安装包包含私有 Python/NumPy 评分运行时，无需安装系统 Python 或单独运行 ModelTrace 服务。

在宿主「插件管理 → 安装插件 → 上传包」上传：

`dist/personal.modeltrace-health-1.5.1-x86_64-unknown-linux-gnu.tar.gz`

启用后打开「账号降智检测」，进入「参数配置」选择已有计量 Key，保存后即可单号或批量检测。检测请求由宿主按指定账户 ID 执行，使用该账户绑定的代理并计入所选 Key。Key 的账户分组和模型权限仍由宿主校验。页面仅接收 Key ID 和名称。

运行时首次检测会解出约91MB文件，目标目录需可写、可执行并有足够空间。自动跳过 `noexec` 临时目录，解包失败时清理残留并尝试 `/var/tmp`，兼容 Docker 中仅64MB且禁止执行的 `/tmp`。可用宿主进程的 `MODELTRACE_RUNTIME_DIR` 指定首选目录，或用 `TMPDIR` 修改系统临时目录。解包不恢复不必要的文件时间戳；异常会显示具体条目和系统错误。

### 1.5.0 请求窗口与评分提速

- 单次30秒维护回调中的请求上限从约28秒调整为约29秒，保留流清理、样本校验、评分和保存的时间。
- 请求前预加载本次指纹库；有效样本不再固定等待剩余6秒才评分，利用当次回调的剩余预算立即评分。仅在实际预算不足时保留样本，下一次优先评分，不重发请求。
- 账户列表、历史和报告将「未命中降智规则」显示为「未降智」，删除进度与请求记录中的推理KB字段。
- 原实例升级保留配置、自动计划、指纹库和历史。

### 1.4.6 部分结果接纳与调度提速

- 请求达到宿主预算或配置超时、流正常关闭但缺少完成事件、输出达到 token 上限时，保留已收到的正文，丢弃末尾可能尚未输出完整的数字，再按原有门槛校验：至少 `max(80, ceil(期望数量 × 55%))` 个有效数字，至多4096个。通过后继续评分，报告标记「已接纳部分结果」；仅推理、数字不足、明确上游失败、内容过滤或协议错误仍不接纳，取消优先。
- 实时进度和请求记录分别统计正文、可见推理/推理摘要的 UTF-8 字节数，保留流数据总量；完成事件的正文及推理快照不与已收到的增量重复计数。宿主未返回的隐藏推理无法按字节统计，推理字节数为0不代表没有消耗推理 token。
- 收到完成事件后立即结束接收，不再等额外的流结束通知。预算充足时，同一次维护回调内连续完成评分、自动关闭调度、移组及后续账户检测；更新检查延至空闲时，减少步骤之间约30秒的调度等待。后续请求使用当前剩余预算；预算不足时安全保存并等待下次调度，每个任务每次回调仍最多推进一轮或一次失败尝试。
- 原实例升级保留配置、指纹库和历史，无需修改现有参数。宿主每次维护回调30秒的限制仍然存在，模型持续推理且没有足够正文时仍可能超时。

### 1.4.5 检测来源独立

- 同一账户的手动与自动检测分别排队、去重、重试并保留报告；自动任务不会禁用手动检测按钮，手动任务不会使定时检测跳过该账户。两类就绪任务交替执行，各自保留完整的检测与复测流程。
- 「停止手动队列」与「停止自动队列」分别取消对应来源的任务，不改变另一队列或自动计划。取消单个任务仍可在检测历史中操作。
- 账户列表和检测历史的检测时间后显示「（手动）」或「（自动）」。顶部保留自动检测开关状态和周期，「下次检测」仅显示自动计划时间，不再附加来源，也不受手动任务的开始、重试或取消影响。

### 1.4.2 进度显示修复

- 修复慢回答时进度长期停在「正在校验样本」的误读：回答在维护预算最后约5.5秒内到达时，有效样本已保存、评分按设计延至下一次维护回调，但阶段标签停留在校验中并累计约30秒。现在样本通过校验后阶段显示为「已获得有效样本，等待评分」。
- 检测行为与1.4.1完全一致：评分在下一次回调执行，不重发模型请求，不消耗采样尝试。新增对应RPC回归测试。

### 1.4.1 超时修复

- 修复1.3引入的请求时间回归：准备与请求合并后，准备耗时及额外6秒预留会使请求提前超时。用实际1.2和1.4二进制对照，25秒返回的相同模拟请求在1.2成功、1.4约22.5秒超时；1.4.1回归测试通过。
- 请求在30秒维护回调中可用约28秒。冷启动准备较慢时，先保存挑战，下次回调再发请求，不消耗采样尝试；已获得的有效样本继续保留，评分可以延后。
- 等待重试直接显示失败原因和尝试次数；报告自动刷新失败记录，显示耗时、接收流数据量和实际请求窗口。连续两次超过维护调用预算时终止任务，避免继续发送相同的超时请求；普通失败和用户配置的请求超时仍最多尝试5次。
- 更新原实例保留配置、指纹库和历史。更新后对之前超时或中断的任务重新发起检测。

## 使用

- **账户检测**：列出全部账户；按订阅、状态和分组组合筛选，搜索名称、邮箱或账户ID。支持10/20/50/100条分页、勾选当前页、跨页批量检测。首版检测OpenAI账户；其他提供方会显示不支持。
- **参数配置**：一套全局配置，手动和定时共用。请求模型支持目录选择与手动输入；支持计量Key、temperature、推理强度、输出上限、超时、降级名单、别名和阈值配置。宿主不接受的请求参数会终止本次任务并显示错误类别。
- **检测历史**：查看每轮全部候选概率、家族概率、触发原因、请求ID、配置快照和指纹库版本。删除历史不会恢复已停用账户。

默认配置：

| 参数 | 默认值 |
| --- | --- |
| 请求模型 | `gpt-6.1-sol` |
| 降级模型 | `gpt-5.6-luna` |
| 低置信度阈值 | 20% |
| 降智阈值 | 90% |
| 连续确认轮数 | 1 |
| 低置信度额外复测 | 最多1轮 |
| 重试与复测间隔 | 10秒 |
| 推理强度 / 输出上限 | low / 4096 tokens |
| 请求超时 | 默认120秒，无固定上限，允许非负整数秒；0表示不设置插件超时 |
| 定时检测 / 自动停用 / 自动移组 / 自动检查更新 | 默认关闭 |
| 历史保留 | 30天，可配置1至365天，最多500条并受存储预算限制 |

### 判定与请求预算

每轮只发送一次检测请求，获得一个有效回答后评分；普通失败时最多重试到五次采样尝试。无效回答、限流与超时消耗尝试预算；认证、权限或参数错误立即终止，连续两次完整请求窗口的宿主预算超时也提前终止。失败或证据不足均不会关闭调度或移组。

1. **低置信度**：最高候选概率严格小于20%，即所有候选均低于阈值，自动重新检测。
2. **疑似降智**：请求模型（应用别名后）不在降级名单内，最高候选在降级名单内且概率大于等于90%。默认一轮即可确认；任何非疑似结果中断连续计数。
3. **其他结果**：高置信度且不命中降级名单为「未降智」；其余为「证据不足」。

例如请求 `gpt-6.1-sol`，一轮以至少90%概率识别为 `gpt-5.6-luna`，才确认降智。直接请求luna，或别名指向luna时，命中luna不会触发降智。

每个任务总轮数上限为「连续确认轮数 + 低置信度额外复测预算」，默认最多2轮、10次请求（含失败重试）；多数任务一轮结束。低置信度复测还单独受其预算约束。确认降智后，开启自动停用时将宿主账户 `enabled=false`；开启移组时将 `groupIds` 替换为指定的单个分组，两项可以同时开启。操作前后核对账户身份与结果，各项独立保存状态，失败不阻止另一项。报告中的重试仅执行对应操作，不重新采样；已处于目标状态时跳过重复写入。预算充足时同次维护回调依次执行待办操作，剩余预算不足时才等待下次调度。管理员负责恢复账户调度及原分组。

后台按账户任务串行执行。宿主在每次维护回调结束后约30秒再次调度。预算充足时一次回调连续完成评分、确认后的账户操作及后续账户检测；冷启动准备较慢时先保存挑战，下一次回调再发请求，避免准备挤占请求窗口。剩余预算不足时保留已完成的安全步骤，下次继续。首次开始、重试和复测仍受宿主调度间隔影响；倒计时结束表示可执行，仍需等待调度。关闭页面不影响执行；取消会通知执行器结束等待并关闭进行中的模型流，不再等完整请求超时。

请求超时默认120秒，0表示不设置插件请求超时。执行器取配置超时与宿主剩余预算中的较短值；1.5.0将30秒维护回调中的请求窗口调整为最长约29秒。指纹库在请求前预加载，样本通过校验后尽量在同次回调评分；实际剩余预算不足时才显示「已获得有效样本，等待评分」，下一次优先继续评分，不重发请求。报告记录实际请求窗口、正文和流数据量。超时或截断时，部分正文通过原有样本校验后可继续评分；有效样本不足时按失败规则重试。连续两次完整请求窗口的宿主预算超时会停止重复请求；同次回调后续账户使用缩短窗口时仍保留普通重试预算。RS 3.29.7 的维护回调总预算为30秒，配置120秒不代表本次回调可以等待120秒。升级保留原配置；已提交任务继续使用原配置快照。真正的进程重启或存储失败导致请求结果不确定时，仍标记中断，需新建检测以避免重复请求。

### 配置保留与备份

参数存入宿主 `control/main` 私有状态，与插件安装目录及版本号分离。保持原插件实例 ID 更新版本，宿主会沿用同 schema 的状态，配置、历史与指纹库继续保留；1.3 配置载入1.4时自动补齐新字段，自动移组默认关闭。使用宿主的升级/版本切换功能更新现有实例，避免每次删除后新建实例。

在「参数配置 → 配置备份」点击「导出配置」，使用「复制配置 JSON」将内容保存为 `modeltrace-health-config.json`。宿主隔离页面限制直接下载，因此始终提供可选中复制的完整 JSON；独立打开时也会下载文件。文件包含已保存参数、Key ID、目标分组 ID、定时范围及镜像地址，不含 Key 密钥、账号凭据、检测历史或指纹库数据。未保存的表单修改不会被导出。

需要重装或迁移时，点击「导入配置」选择备份，校验通过后载入表单；核对新平台的计量 Key、目标分组、账户 ID 和可用模型，再点击「保存全部参数」。导入文件不能读取其他实例的私有状态，因此不会自动跨实例恢复；版本字段用于后续兼容，亦接受1.3格式的完整原始参数 JSON。未知字段、无效阈值、超过250KB的文件会被拒绝，不会覆盖已保存参数。

### 自动定时

支持固定间隔（分钟）和指定IANA时区的每日时刻。每日时刻遇到夏令时缺失分钟时，在之后首个有效分钟执行；重复时刻当日只运行一次。

范围可保存订阅、状态、分组和关键词筛选条件，运行时重新匹配以纳入新账户；也可保存固定账户ID。定时只检测启用的OpenAI账户，仅跳过已有活动自动任务的账户；活动手动任务不影响定时提交。手动检测不改变定时计划的下次执行时间。错过的时间点合并一次，不补跑全部历史时间点。每次最多提交500个账户，超出会在配置页显示错误，需缩小范围。

### 指纹库在线更新

在「参数配置 → ModelTrace指纹库」点击「检查更新」，随后「下载并应用」。也可开启后台定时检查，默认间隔24小时；应用始终由管理员点击。

来源固定为 `xqy2006/ModelTrace` 默认分支的 `data/unified_bank.json`。先解析提交SHA，再按该提交下载，显示当前提交、SHA-256、建库时间、完整模型列表，以及新库新增和移除的模型。可设置HTTPS镜像前缀，地址拼接为 `镜像前缀/完整GitHub地址`。

下载限20MiB，压缩后存储限3MiB；指纹库检查仍受宿主维护调用预算约束。下载后校验schema、指纹方法、模型唯一性与顺序、矩阵维度、有限数值、校准参数，并离线跑通1/2/3样本评分。只有全部通过才切换版本，库不兼容时提示升级插件。在线更新仅加载JSON数据；算法与Python运行时随插件更新。

提供「回退上一版本」「恢复内置库」。本地保留内置库、当前库、上一库及活动任务引用的旧库。更新、回退不改变已开始任务的库；整个任务及复测均固定同一库。旧报告保留当时的概率，不重新计算。新库移除正在配置使用的降级模型或别名目标时，阻止应用并提示冲突。下载失败或保存中断保留当前库，下次载入清理暂存数据。所有持久库分块存入宿主私有状态，重启及同实例升级保留。

ModelTrace概率是当前候选库内、均匀先验下的相对概率；库外模型仍会归入现有候选。「降智」是用户配置规则的检测标签，不是智商测量或模型身份认证。

基础镜像已缓存时可向 `build_runtime.py` 传 `--base-tar /path/python-base.tar`。脚本验证固定镜像配置、各镜像层和NumPy wheel哈希，不依赖Docker守护进程。`scripts/package.sh` 可串联构建和校验，需在已激活的开发环境运行。

未修改 Python/NumPy 依赖时，也可用 `.venv/bin/python scripts/refresh_runtime.py /path/to/previous-release.tar.gz` 复用已验证发布包中的固定运行时，并刷新评分与上游源码。必须同时提供原包的 `.sha256` 文件；脚本校验包与全部资源摘要。依赖变更时使用完整构建脚本。

## 接口

插件ID：`personal.modeltrace-health`。所有管理接口使用宿主管理员身份。

| 方法 | 插件相对路径 | 用途 |
| --- | --- | --- |
| GET | `api/bootstrap` / `api/accounts` / `api/models?keyId=...` | 配置、账户与可见模型目录 |
| POST | `api/config/preview` | `{config}` 校验与补齐默认值，仅预览不保存 |
| POST | `api/config` | `{config, revision}` 保存配置，版本冲突拒绝覆盖 |
| POST | `api/submit` | `{accountIds, requestId}` 幂等提交 |
| GET | `api/jobs` / `api/report?id=...` | 任务列表与报告 |
| GET | `api/progress?since=...` | 轻量进度快照；版本未变化时返回 `changed=false,jobs=null` |
| POST | `api/cancel` / `api/delete` / `api/retry-disable` / `api/retry-group` | `{id}` 取消、删除历史、重试关闭调度或移组；取消支持可选 `source=manual/schedule` 分别停止队列；省略id与source时停止全部队列 |
| POST | `api/banks/check` / `apply` / `rollback` / `builtin` | 检查、应用、回退与恢复内置库 |
